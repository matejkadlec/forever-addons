## Coupling with the feed service

- `services/forever-market-feed` ports `scan/Diff.lua` / `FM.FinalizeSnapshot` to Python and writes the load-on-demand AddOn `ForeverMarket_Feed`, which `scan/Feed.lua` imports; its `.toc` title is "Forever Marketplace Feed" since FRV-198 (`FEED_TOC` in `feed.py`, "Forever Market Feed" before), and `LoadFeed`'s error line in `scan/Feed.lua` quotes the same title: change both together (FRV-2 plans the module name "Forever Marketplace [Data Feed]")
- A change of the record format, of `scan/Diff.lua` or of `FM.FinalizeSnapshot` must be made on both sides in the same change (see [`services/forever-market-feed/AGENTS.md`](../../services/forever-market-feed/AGENTS.md)); a change on the service side deploys the feed server when it merges
- `r.last.gear` (FRV-200) is written by `FM.FinalizeSnapshot` but is no part of the records, the fingerprints or the diff; since 1.55 (FRV-201) the feed builds the same map from the API's item auctions (`feed.py` `gear_variant` = `FM.GearVariant`, `aggregate` / `gear_entries` = `AddGear` / `GearEntry`; commodities never), sends it with the latest snapshot (`state["prev"]["gear"]`, the server's `/v1/feed` `last.gear`, `checked_feed`'s `GEAR_RE`, `render_feed`'s `gear = {...}`; `FEED_VERSION` stays 1, the field is optional on both sides) and `scan/Feed.lua` writes it into `r.last`. A change of `FM.GearVariant` or of the entry format is made on both sides with `tests/fixtures/gear_cases.txt` (`gearfeed_test.lua`, `tests/feed/test_feed.py` `GearTest`). The API names no seller: after a feed import a variant you list yourself is in the map (a deep scan leaves yours out)
- The shared fixtures in [`tests/fixtures/`](../../tests/fixtures/) state the expected diff results and records; `tests/run.sh` checks both sides against them, so such a change updates the fixtures too ([`tests/README.md`](../../tests/README.md))
